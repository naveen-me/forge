C3 PRE-FLIGHT — USE EXISTING WPE ARTIFACT (DO NOT REBUILD WPE)
=========================================================================

Goal
-----
Verify the migrated production WpeHtmlRenderer against the existing WPE
WebKit 2.52.5 artifact in GitHub Actions.

Constraints
-----------
- Do NOT rebuild WPE.
- Do NOT create another WPE build workflow.
- Do NOT modify the WPE build workflow.
- Do NOT troubleshoot the root-owned local build directory here.
- Do NOT install random ICU packages here.
- Only one test is in scope:
    test_wpe_production_renderer
- C3 30 FPS benchmark is explicitly out of scope.
- C3 PASS is explicitly not claimed.

GitHub Actions artifact access
------------------------------
The new workflow uses the GitHub CLI workflow command context to look up the
latest successful C1 WPE build run and then download the matching artifact by
name. That is the smallest safe path that does NOT rebuild WPE and does NOT
need a separate manually tracked artifact id.

If the successful C1 run cannot be found automatically, the workflow will fail
explicitly rather than silently fall back to a wrong artifact.

ICU/runtime compatibility
-------------------------
The C1 helper scripts show ICU 74 and libxml2 2.9 were packaged separately for
this host when needed:
  scripts/download_icu74.sh

The new validation workflow does not attempt to solve that automatically. It
leaves the runtime dependency question to be answered by the runner result.

If the runner shows missing libraries at ldd time or a startup failure, the
next step is to inspect the uploaded artifact log and decide whether the
artifact itself already carries the needed runtime libraries or whether the
runner needs additional packages. That decision should be made from evidence,
not by guessing.
